
## Chapter 03 Requirements Specification 

### 3.1 Functional Requirements 
* The system shall allow users to browse an extensive catalog of cosmetic products, categorized by Face, Lips, and Eyes.
* The system shall offer real-time AR try-on functionality, projecting products directly onto the user's face using the device's camera.
* The system shall enable administrators to dynamically add, edit, or remove new products, categories, and color hex codes from the backend database.
* The system shall support user authentication via email, providing secure profiles to save favorite products and virtual try-on preferences.
* The system shall accurately detect facial landmarks to ensure cosmetic products (like lipstick, eyeshadow, blush, and mascara) align correctly with the user's facial geometry.

### 3.2 Non-Functional Requirements 
* **Performance:** The AR rendering engine must operate at a minimum of 30 frames-per-second (FPS) to maintain the illusion of a realistic mirror.
* **Accuracy:** Facial landmark tracking must respond to rapid head movements seamlessly without severe visual desynchronization or lag.
* **Security:** User credentials and profile metrics must be encrypted and securely processed through industry-standard cloud authentication protocols.
* **Usability:** The interface must be highly responsive, intuitive, and feature a dark-themed, premium aesthetic that caters to mobile environments.
* **Cross-Platform Compatibility:** The application architecture must be capable of deployment on both Android and iOS systems via a single unified codebase, while interacting with native rendering hardware.

### 3.3 Hardware / Software Requirements 
* **Hardware:** Modern smartphone equipped with a front-facing camera capable of capturing at least 720p resolution video streams. A device with hardware-accelerated machine learning processing capabilities (e.g., Apple A-Series Bionic chips or equivalent Snapdragon architectures) is highly recommended for optimal AR frame rates.
* **Software:** iOS 14.0 or higher / Android 10.0 or higher.
* **Development Stack:** 
    * Frontend: Flutter Framework (Dart)
    * Native Render Plugins: Swift/Metal (iOS), Kotlin/OpenGL (Android)
    * Computer Vision: Google MediaPipe FaceLandmarker
    * Backend: Google Firebase (Firestore, Authentication, Storage)

### 3.4 Networking Requirements (Optional) 
* A stable broadband connection (Wi-Fi or 4G/5G) is necessary for initial application launch, loading high-resolution cosmetic textures, streaming database updates, and authenticating user credentials.
* The AR tracking and facial mesh processing occurs locally on-device and does not require constant cloud connectivity for rendering.

## Chapter 04 Feasibility Study 

### 4.1 Operational Feasibility 
The system is deeply user-centric, mimicking the physical act of looking into a mirror. The interface utilizes standard mobile design patterns—like swiping to change shades and a simple bottom-drawer navigation—drastically reducing the learning curve for users of all demographic backgrounds. Administrators interacting with the Firebase backend are provided with intuitive, no-code graphical dashboards engineered by Google, ensuring operational management of products remains trivial.

### 4.2 Economical Feasibility
The project prioritizes open-source and free-tier scalable technologies. Utilizing the Flutter framework effectively halves the development cost by consolidating iOS and Android production into a singular codebase. Furthermore, leveraging Google Firebase eliminates the need for maintaining proprietary physical servers or managing complex DevOps deployment pipelines. All primary SDKs (like MediaPipe) are free to use, ensuring the project aligns perfectly with a highly constrained student development budget.

### 4.3 Technical Feasibility 
The development team possesses extensive knowledge of object-oriented programming, modern cross-platform mobile frameworks, and cloud database architecture. While native AR rendering involves intricate mathematical matrix projections, combining Flutter’s MethodChannels with native Swift/Kotlin code enables full access to low-level hardware optimizations. The selection of MediaPipe—an industry-proven machine learning library—ensures highly performant real-time face tracking without requiring the team to build custom, computationally expensive neural networks from scratch.
